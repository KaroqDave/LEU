# M0 foundation status

M0 provides a working Windows x64 Electron application with TypeScript, React, and a Rust helper. The program browser uses eight explicitly labeled sample records. Real Windows inventory begins in M1.

## Implemented behavior

- Installed apps, Activity, and Settings navigation, search by application or publisher, installation scope filters, sorting, selection, and program details.
- System light and dark appearance, keyboard focus, labeled inputs, and unavailable uninstall actions with an explanation.
- A sandboxed renderer with Node integration disabled, an isolated preload bridge, and checked IPC senders.
- Bundled production assets served through a restricted `leu://app` protocol with a content security policy.
- A Rust executable packaged outside `app.asar`, with a statically linked C runtime and no separate Rust runtime installation required for users.
- Protocol version 1 over private stdio, request identifiers, JSON schema validation in the client, strict request parsing in Rust, bounded frames, and a handshake deadline.
- Clear missing helper, invalid response, incompatible protocol, timeout, and crash outcomes. Helper status changes reach the interface without polling, and users can reconnect.
- Helper shutdown on application close. The native helper also exits when its stdin closes.
- MIT licensing, dependency lockfiles, contributor instructions, and a Windows CI workflow.

The native allowlist contains only `engine.version`. M0 does not access uninstall registry records, launch uninstallers, delete leftovers, or request elevation.

## Local verification

The Windows development host passes strict TypeScript checks, 17 TypeScript tests, 7 Rust tests, Rust formatting, Clippy, and Prettier checks. Client tests exercise fragmented responses, malformed responses, mismatched request identifiers, protocol mismatches, missing executables, deadlines, crashes, and concurrent reconnect requests.

The packaged smoke test verifies the real Rust handshake, helper execution from a path containing spaces and Unicode, renderer isolation, the bridge allowlist, search and empty states, navigation, reconnect, a deliberately terminated helper, recovery from that termination, and helper exit when the window closes. It captures both light and dark screenshots.

The development launch has also been checked with Forge's local server, including CSS, SVG branding, restricted IPC, and the real helper. `pnpm make` produces a Windows zip.

The [first GitHub-hosted Windows run](https://github.com/KaroqDave/LEU/actions/runs/39172200119) also passed dependency installation, all source and protocol checks, Windows packaging, and the packaged application smoke test. A clean Windows VM build outside CI remains to be verified.

## Initial performance baseline

An automated packaged run on 18 October 2026 used Windows build 26300, an AMD Ryzen 9 9950X3D with 32 logical processors, and 64 GiB RAM. The build used Electron 44.9.0, React 19.3.1, and Rust 1.99.1 with eight demo records.

| Measurement                                            | Observed value        |
| ------------------------------------------------------ | --------------------- |
| Launch through searchable UI and helper connection     | 5.58 seconds          |
| Summed private working set across the app process tree | 124.10 MiB            |
| Summed private committed bytes                         | 313.25 MiB            |
| Sample idle CPU as a share of the whole machine        | 0.01 percent          |
| Measurement interval                                   | 11.16 seconds         |
| Native helper executable                               | 305152 bytes          |
| Renderer JavaScript compressed with gzip               | Approximately 72 KiB  |
| Packaged application directory                         | Approximately 369 MiB |
| Windows zip                                            | Approximately 152 MiB |

This is one automated launch with Chromium debugging enabled and a short idle sample, rather than the roadmap's 30 cold launches and 60 second idle measurement. The startup observation exceeds the provisional 3 second target. Profile actual application readiness separately from debugging attachment and repeat the defined benchmark before evaluating that target. The dataset also needs to grow to representative live inventories in M1.

Private working set and private committed bytes describe different memory usage and should not be compared as the same metric. The package size is dominated by Electron; the application archive itself is roughly 0.4 MiB.

The smoke command writes fresh raw measurements and screenshots to `out/smoke`. The values here record an early M0 sample and are not release performance guarantees.

## Repository and release setup

The source repository is [KaroqDave/LEU](https://github.com/KaroqDave/LEU), with a Windows CI workflow and [private vulnerability reporting](https://github.com/KaroqDave/LEU/security/advisories/new). See [SECURITY.md](../SECURITY.md) for reporting guidance. Public release signing is part of M5; the current package is an unsigned development artifact.

The next implementation milestone is read-only Windows registry inventory, preserving installation scope and registry view provenance. The demo provider can remain available for deterministic interface tests.
